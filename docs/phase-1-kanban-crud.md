## Goal

Build a simple kanban board for the Cloud Computing course that demonstrates **Backend as a Service (BaaS)**: the app has no backend of its own, and the browser reads and writes data directly to Firebase Realtime Database. The board had to support full CRUD (Create, Read, Update, Delete) and stay in sync in realtime.

## Result

- A board with three columns — **To Do**, **In Progress**, and **Done** — each with a task count and a "Belum ada task" placeholder when empty.
- **Create:** a modal form for a new task (title, description, status, priority, start date, deadline).
- **Read:** tasks are placed in the column matching their `status` and update live in every open tab and device, including changes made in the Firebase Console.
- **Update:** the same modal form edits a task's details, and a status dropdown on each card moves it to another column.
- **Delete:** a delete button on each card opens a confirmation dialog before the task is removed permanently.
- All UI text is in Bahasa Indonesia.

## Project setup

Before the first feature, the project was set up as follows:

- **Next.js 16** (App Router) with React 19 and TypeScript, created with `create-next-app`. It was converted from npm to **Yarn 1** (`packageManager: yarn@1.22.22`), and `package-lock.json` was removed so only `yarn.lock` remains.
- Dependencies: Firebase JS SDK, Sass (for SCSS Modules), React Hook Form, and Font Awesome Pro. The Pro packages come from Font Awesome's private registry, configured in `.npmrc` with a token read from the `FONTAWESOME_PACKAGE_TOKEN` environment variable.
- **Inter** as the only font, in four weights (400, 500, 600, 700) of the 18pt optical size, loaded with `next/font/local`. The 50 unused files from the Google Fonts download were removed.
- **Prettier** with automatic import sorting (`@trivago/prettier-plugin-sort-imports`), double quotes, and trailing commas.
- `CLAUDE.md` as the project specification: data model, CRUD mapping, components, UI design, and code conventions.
- Clean-up: macOS metadata files (`._*`) that had been committed by accident were removed and added to `.gitignore`.

## Data model

Each task is stored at `/tasks/{taskId}`, where `taskId` is the key generated by Firebase's `push()`:

| Field | Type | Description |
|---|---|---|
| `title` | string | Task title (required) |
| `description` | string | Short description (optional) |
| `status` | `"todo"` \| `"in_progress"` \| `"done"` | The column the task appears in |
| `priority` | `"low"` \| `"medium"` \| `"high"` | Shown as a colored badge |
| `startDate` | string (`YYYY-MM-DD`) | Start date (required) |
| `deadline` | string (`YYYY-MM-DD`) | Due date (required, on or after `startDate`) |

## Components

| Component | What it does |
|---|---|
| `Button` | The shared button: `color` (primary, secondary, danger, warning, neutral), `variant` (solid, outlined, text), `size` (small, medium, large), and optional Font Awesome icons on either side. A button with only an icon becomes square and requires an `aria-label`. The touch area is always at least 44×44px. |
| `Modal` | A base modal built on the native `<dialog>` element. Opened and closed through `isOpen` / `onClose` props. Closes on Escape and on a click on the overlay, with open and close animations. Components inside it can close it with `useModal().close()`. |
| `ModalForm` | The task form, built with React Hook Form and used for both create and edit. Validates required fields and that the deadline is not before the start date. Clicking anywhere on a date field opens the calendar. Shows an error and stays open if saving fails. |
| `TaskCard` | A single task: priority badge (Rendah / Sedang / Tinggi), title, description, date range, status dropdown, and edit and delete buttons. A task in Done has its title struck through and faded. |
| `ConfirmDialog` | A generic confirmation dialog (`role="alertdialog"`) with an optional icon and a `danger` variant. Disables its buttons and shows "Memproses..." while the action runs; shows the error and stays open if it fails. |

`tasksService.ts` exposes `subscribeTasks` (`onValue`), `createTask` (`push`), `updateTask` (`update`), and `deleteTask` (`remove`) through a default export, `taskService`.

## Technical decisions

- **One service layer for Firebase.** Components never import from `firebase/*`; every read and write goes through `tasksService.ts`. This keeps Firebase-specific code in one place and makes components easier to read.
- **Firebase starts lazily.** `getDb()` initializes Firebase on first use, so it only runs in the browser and not while Next.js prerenders the page.
- **A controlled modal.** The first version of `Modal` exposed `open()` and `close()` methods through a ref. It was changed to `isOpen` / `onClose` props, as the React documentation recommends, so the open state lives in one place (the parent) instead of two.
- **The native `<dialog>` element.** The browser handles focus trapping, the Escape key, and stacking above the page, so the modal needs no portal or `z-index` handling.
- **State is kept while a modal closes.** The task being edited or deleted is not cleared when the modal closes, so the title and contents don't change during the closing animation.
- **No separate column component.** The three columns are rendered directly in the board, which kept the code simple for three fixed columns.
- **Dates are formatted in UTC.** `Intl.DateTimeFormat` with the `id-ID` locale and `timeZone: "UTC"` shows full month names (for example, "20 September – 24 September") and never shifts a date by a day for users in other time zones. The year is shown only when the start date and deadline are in different years.
- **Instant status changes.** Firebase updates local listeners before the server confirms a write, so a card moves to its new column immediately; if the server refuses the write, Firebase moves it back.
- **Code conventions.** Explicit TypeScript types on every variable, parameter, and return value; JSDoc on functions; BEM-style class names in SCSS Modules. React Compiler is enabled, so `useCallback` and `useMemo` are not needed.
- **Open database rules (temporary).** With no login yet, the README told users to set `/tasks` to public read and write. This was replaced with proper rules in Phase 2.

## Problems and fixes

| Problem | Cause | Fix |
|---|---|---|
| WebStorm showed `Invalid regular expression … Range out of order` on save | WebStorm's Prettier settings used `.prettierrc` as the *ignore* file | Switch WebStorm to automatic Prettier configuration |
| The calendar icon in date fields was invisible | The template's dark `color-scheme` drew a light icon on a white field when macOS was in Dark Mode | Set `color-scheme: light` in `globals.scss` |
| The modal appeared in the top-left corner | The global `* { margin: 0 }` reset removed the `margin: auto` the browser uses to center a `<dialog>` | Add `margin: auto` to the modal |
| The calendar opened only when its icon was clicked | Default browser behavior | Call `showPicker()` when the field is clicked |
| `import taskService` failed to compile | `tasksService.ts` had no default export | Add a default export |

## How it was tested

- Lint, type checking, and a production build after each step.
- Component behavior (modal opening, closing, focus, animations, and the form's validation) was checked in headless Chrome on temporary routes, which were deleted afterwards.
- Create, read, update, and delete were tested against the real Firebase database with temporary test tasks, which were deleted afterwards.

## Known limitations at the end of the phase

- The database was open: anyone who knew its URL could read and change every task.
- The mobile layout (tabs per column and a floating add button below 1024px) was not built.
- "Belum ada task" appears briefly before the first data arrives, and errors while loading tasks are only logged to the console.
